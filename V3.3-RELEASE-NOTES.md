# Payment Platform V3.3 — Stabilization Release

## What was changed

- Added a foundational `000_v3_3_core_bootstrap.sql` migration so a fresh MySQL database contains the core entities required by the application before later feature migrations run.
- Added `009_v3_3_error_reporting.sql` and persistent `error_reports` storage.
- API errors now return a stable error code and request ID and are persisted with route, method, status, sanitized request data, headers, query/params, user/tenant context and development stack trace.
- Sensitive fields are redacted before persistence (authorization, API keys, passwords, secrets, tokens, card/CVV-like fields, etc.).
- Added `GET /v1/error-reports` for authorized operators.
- API key handling in the web console now recognizes `pk_test_...` credentials as `Api-Key` instead of incorrectly sending them as `Bearer` sessions.
- Removed the repeated API-key input from the global console header. Authentication mode is now shown as a status badge; API keys remain managed under `API & Webhooks`.
- Added `Errors` to the console for reviewing persisted error reports.
- Sidebar now scrolls internally and has Previous/Next navigation plus a mobile navigation fallback.
- Web development example now enables the real merchant login by default (`VITE_REQUIRE_LOGIN=true`).
- Version identifiers updated to `3.3.0`.

## Authentication model

1. Merchant dashboard: email/password -> user session -> `Authorization: Bearer <session>`.
2. External API clients: API secret -> `Authorization: Api-Key <secret>`.
3. Development-only tenant bypass remains available when the API runs outside production and no credential is supplied.

## Sandbox

The existing SandboxProvider remains the default payment provider and is not dependent on a real processor API key.

## Accounting integration

The current archive contains a real Zoho Books OAuth connector. It does **not** contain a completed Imkan Books connector. V3.3 therefore keeps the integration layer provider-neutral and does not claim Imkan Books is connected until its official API/authentication details are supplied.
