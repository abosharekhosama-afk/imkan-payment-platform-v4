**التاريخ:** 13 أغسطس 2026  
**المشروع:** Payment Platform V3.4.1  
**الجهة:** الإدارة

---

## 1. الخلاصة

أُغلق اليوم مسار **مراجعة الحساب البنكي للتاجر من لوحة المنصة**، وتأكد بـ **اختبارات آلية**. كما أُعيد تصميم **لوحة التاجر للموبايل**، وأُصلح خطأ **قبول دعوة عضو الفريق** عند إنشاء الاسم وكلمة المرور.

المنتج جاهز للتحضير لإطلاق **إنتاج محدود**: تحصيل البطاقات عبر **Stripe Live في حساب المنصة**. التحويل التلقائي إلى IBAN كل شركة **ليس** ضمن هذا الإصدار.

---

## 2. ما أُنجز اليوم

### 2.1 عمليات الحساب البنكي (مسار التشغيل)

سابقاً كان التاجر يضيف IBAN عبر النظام، دون شاشة للمنصة للمراجعة أو التفعيل.


| البند                                        | الحالة |
| -------------------------------------------- | ------ |
| قائمة المراجعة: `/platform/bank-accounts`    | مكتمل  |
| اعتماد / رفض الحساب (مع التحقق الثنائي TOTP) | مكتمل  |
| تفعيل المنصة بعد حالة «تم التحقق»            | مكتمل  |
| تفعيل / إيقاف / تعيين افتراضي من التاجر      | مكتمل  |
| واجهات API: جلب الحساب وتفعيل الأدمن         | مكتمل  |


**المعنى التشغيلي:** يمكن اعتماد IBAN الشركة وفتحه لتسجيل عمليات الصرف. هذا **لا يحوّل مالاً إلى البنك تلقائياً**.

### 2.2 الاختبارات الآلية

- الملف: `tests/phase3-merchant-kyb.test.ts`
- النتيجة: **12 من 12 ناجحة**
- تغطي: دورة KYB، تشفير وإخفاء بيانات البنك، عزل الشركات، و**تفعيل مسؤول المنصة** لحساب تم التحقق منه



### 2.3 تجربة الاستخدام (موبايل ووضوح النصوص)


| التغيير                                                     | الفائدة                                                                   |
| ----------------------------------------------------------- | ------------------------------------------------------------------------- |
| هيدر موبايل مختصر (قائمة + اسم المنتج فقط)                  | أزرار اللغة والمظهر والخروج لم تعد تملأ نصف الشاشة                        |
| قائمة جانبية مسطحة بأيقونات دون قوائم قابلة للطي            | تنقّل أسرع على الهاتف والحاسوب                                            |
| نقل الخروج واللغة والمظهر إلى القائمة الجانبية وصفحة المظهر | هيدر أنظف مع بقاء الإعدادات                                               |
| أدوار وحالات مفهومة للمستخدم                                | مثلاً: المالك بدل `MERCHANT_OWNER`، وبانتظار الدفع بدل `REQUIRES_PAYMENT` |
| شيمر تحميل بدل اللودر الدائري                               | مظهر أحدث أثناء الانتظار                                                  |
| إرسال مفتاح عدم التكرار عند قبول الدعوة                     | المدعو ينشئ اسمه وكلمة المرور دون خطأ Idempotency                         |




### 2.4 أعمال سابقة في نفس الدورة (المال والرسوم والصرف)

ما زالت ضمن نفس الكود وجاهزة مع هذا التسليم:

- تسجيل تقسيم الرسوم عند نجاح الدفع (رسوم المنصة / رسوم المزود / الصافي)
- كشف حساب للتاجر مع تصدير CSV
- توجيه إقليمي (الشيكل → محول فلسطين؛ عملات الخليج → PayTabs؛ الدولار/اليورو → Stripe)
- حساب بوابة لكل شركة (ربط البوابة)
- صرف بموافقة مزدوجة: إرسال → اعتماد مع دليل → تعليم كمدفوع
- شاشات المحفظة والتقارير (لم تعد «قريباً»)
- PayTabs المباشر مشروط بمتغير التشغيل؛ محول بنك فلسطين هيكل فقط حتى العقد والمستندات

## 3. ماذا يستطيع الإنتاج وما لا يستطيع



### يمكن بعد إغلاق قائمة التشغيل

- تحصيل بطاقات **Stripe Live** في **رصيد Stripe الخاص بالمنصة**
- منع الدفع حتى تكون حالة KYB مسموحة
- مراجعة IBAN التاجر وتفعيله داخل إمكان
- تسجيل الرسوم وكشوف الحساب و**نية الصرف** بموافقة مزدوجة



### لا يشمله هذا الإصدار

- تحويل بنكي تلقائي إلى IBAN الشركة
- Stripe Connect (حساب Stripe مستقل لكل تاجر)
- تحصيل حي في فلسطين (بنك فلسطين / جوال) حتى يوجد عقد ووثائق API خاصة
- PayTabs الحي للخليج إلا بعد تفعيل العلم التشغيلي وإتمام العقد

**الرسالة المقترحة لأصحاب المصلحة:**  
إمكان طبقة **تحصيل وتشغيل**. تحويل المال إلى بنك التاجر يتم من **لوحة Stripe** (أو حوالة يدوية)، ثم يُسجَّل في إمكان كمدفوع مع رقم الدليل.

## 4. المطلوب قبل الإطلاق الحي (تشغيل، لا ميزات برمجية جديدة)

1. رفع **الكود المصدري فقط** (عدم اعتماد مجلد البناء `dist` كمصدر حقيقة)
2. تشغيل ترحيلات قاعدة PostgreSQL على بيئة الإنتاج
3. Redis مع تخزين حد المعدل على Redis
4. بريد حقيقي والتحقق من البريد الإلكتروني
5. جلسات الكوكيز وبناء الواجهة بنفس إعداد الجلسة
6. مفاتيح Stripe الحية وWebhook على مسار مزود Stripe في الـ API
7. تفعيل بيئة Stripe الحية صراحة في الإعدادات
8. إنشاء مالك المنصة ومسارات Stripe مرة واحدة
9. دفعة تجريبية حية صغيرة: نجاح الدفع → انتهاء الرابط → ظهور القيد في الدفتر / الكشف

## 6. مخاطر والامتثال

- نطاق PCI: عنصر Stripe المستضاف يقلل التعامل مع بيانات البطاقة؛ شهادة SAQ الرسمية ما زالت مطلوبة.
- الأسرار حالياً من متغيرات البيئة، وليست من نظام إدارة مفاتيح سحابي.
- «تعليم كمدفوع» يعني: التحويل تم خارج إمكان ولدينا مرجع، وليس أن واجهة البنك دفعت إلى IBAN.

---



## 7. الخلاصة للإدارة

**الجانب الهندسي لهذه الدورة مكتمل** من حيث: مراجعة البنك في اللوحة، اختبارات KYB/البنك، تجربة الموبايل، وإصلاح قبول الدعوة.

**قرار الإطلاق تشغيلي:** تفعيل Stripe الحي والبريد وRedis والجلسات، ثم تنفيذ دفعة حية واحدة. لا يُسوَّق الصرف التلقائي إلى IBAN حتى يُتعاقد على سكة صرف حقيقية (أو Stripe Connect) وتُبنى في المنتج.
