# Payment Platform V3.4 — Reliability, Authentication & UX Release

## Backend fixes
- Replaced invalid zero-UUID development fixtures with RFC-4122 UUIDs.
- Fixed the merchant lookup used by balance operations (`merchants.id` is now selected as `merchant_id`).
- Added migration `010_v3_4_identity_and_dev_seed.sql` for deterministic local development identities.
- Validation failures now return HTTP 400 with human-readable field messages instead of HTTP 500.
- Added friendly handling for common MySQL/schema errors while preserving full technical details in `error_reports`.
- API health version updated to 3.4.0.

## Frontend fixes
- Removed the repeated API-key input from the global header. API keys remain under Developer/API Keys.
- Fixed payment-link creation to send `amount_minor` instead of the UI-only `amount` field.
- Updated development tenant/merchant/customer IDs to valid UUIDs.
- Added a visible login experience for local development with the seeded account.
- Added Arabic/English language switch with RTL support.
- Hid the visual scrollbar on the sidebar while preserving scrolling.
- Added mobile navigation and responsive layouts for tables, cards, dialogs and checkout.

## Local development
- Payment provider remains `sandbox` by default.
- Seeded local account: `admin@example.test` / `ChangeMe!123`.
- Imkan Books is not claimed as connected; the existing provider-neutral integration architecture remains available for a future official connector.
